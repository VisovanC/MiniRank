MiniRank — Build Process Log

Keyword position tracker (assessment). This file is updated at the end of each M-milestone (M1–M8) and after any major change, so the whole build is explicit and easy to follow. Both the human and the AI edit this file.

Plan

Scope & stack

  • Plain PHP 8 (no framework), PDO + SQLite, vanilla HTML/CSS/JS, one fetch()-driven AJAX refresh.
  • Single user, single website, no login for M1–M8. Multi-project / accounts are stretch goals the schema must not block.
  • M1–M8 in order; repo is committed after each milestone.

Key decisions

  • Controllers vs. lib split: thin controllers (request/response, read superglobals, echo) vs. lib/ pure functions (take data as arguments, never touch superglobals, never echo). Keeps core logic unit-testable later with an in-memory SQLite PDO.
  • Document root: public/ served with php -S localhost:8000 -t public.
  • Routing: plain PHP files as endpoints (3 routes). A front controller can replace them later without touching lib/.
  • Refresh endpoint: public/refresh.php, POST-only, returns JSON.
  • Bootstrap choke point: every entry file requires lib/bootstrap.php — the future home of session/auth/CSRF hooks.
  • Decided 2026-08-17: trend rule = compare latest vs. 7 days earlier with ±1-rank tolerance (a 1-rank move is "stable"); refresh = upsert today's row (idempotent); edit = rename only (history kept), delete = hard delete + cascade; run target = Docker Compose (php:8.2); UI copy = English; keyword search = case-insensitive via SQLite default LIKE (ASCII fold — fine for English keywords; non-ASCII folding intentionally out of scope).

SQLite schema (proposed)

CREATE TABLE IF NOT EXISTS keywords (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  phrase     TEXT    NOT NULL UNIQUE,
  created_at TEXT    NOT NULL DEFAULT (datetime('now'))
);

CREATE TABLE IF NOT EXISTS positions (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  keyword_id INTEGER NOT NULL REFERENCES keywords(id) ON DELETE CASCADE,
  date       TEXT    NOT NULL,                       -- 'YYYY-MM-DD'
  position   INTEGER NOT NULL CHECK (position BETWEEN 1 AND 100),
  created_at TEXT    NOT NULL DEFAULT (datetime('now')),
  UNIQUE (keyword_id, date)
);

CREATE INDEX IF NOT EXISTS idx_positions_keyword_date ON positions (keyword_id, date);
CREATE INDEX IF NOT EXISTS idx_positions_date         ON positions (date);
  • UNIQUE (keyword_id, date) guarantees one position per keyword per day → makes refresh an upsert.
  • Multi-project later = add a projects table + a nullable keywords.project_id column. Today the site URL lives in config.php, so nothing blocks that.

Routing choice

Plain PHP files as endpoints, not a dispatcher: the app has only 3 routes, so a hand-rolled router is indirection without payoff. Each file is obviously a route, which suits an assessment that values clarity. When multi-project arrives, a front controller can dispatch on PATH_INFO — lib/ and the controllers don't change.

CSRF / auth hooks (stretch — slotted in, not built)

  • Every entry file starts with require lib/bootstrap.php. Later, require_auth() and a CSRF token check on POST endpoints go in right there — no rewrite.
  • refresh.php is already POST-only, so CSRF validation later covers exactly one mutation.
  • Sessions/superglobals stay in bootstrap + controllers; lib/ stays clean and testable.

Milestones

M1 — Keywords CRUD (done)

  • Built: schema + auto-init, lib/ pure functions (db, schema, keywords, escape), thin KeywordListController, public/index.php, responsive CSS, Dockerfile + compose, README.
  • Add / edit (rename, history kept) / delete (hard, cascades) / duplicate rejected via the UNIQUE constraint (caught as a constraint violation), whitespace-only rejected by trim+empty validation.
  • Security in place from day one: all queries parameterized, all output through e() (htmlspecialchars). XSS payload renders as literal text.
  • Tests: AI smoke tests over real HTTP (empty state, create, duplicate error, XSS escaping, edit form prefill, update, delete) and manual error testing by the user — duplicate rejected, whitespace-only rejected, XSS rendered literally (not executed), edit/delete work, and data survives a reload (persisted to SQLite, not in-memory).

Prompts & fixes

Three real prompts that mattered — including one that failed — and concrete AI mistakes, how they were caught, and the fix.

1. The foundation prompt (the most relevant one)

Prompt: "I'm building a keyword-position-tracker web app for an assessment. Stack: plain PHP (no framework), PDO for the DB, SQLite, vanilla HTML/CSS/JS, plain AJAX (fetch) for one dynamic refresh action… Do NOT implement anything yet… propose ONLY: 1) directory structure separating controllers from a lib/ of pure functions, 2) the SQLite schema, 3) the routing approach, 4) where CSRF/auth hooks slot in later… also create a process.html kept in three sections (Plan / Prompts & fixes / Retrospective)."

Why it mattered: this single prompt forced a plan-first session and set every architectural decision before the first line of code — the controller/lib split (testable core), the schema's UNIQUE(keyword_id, date) upsert design, plain-file routing, and the bootstrap.php choke point for future auth/CSRF. Everything since builds on these choices.

Mistakes: none in this one — planning only, no code written. (The failed prompt is logged in slot 3.)

2. The M1 build-and-review prompt

Prompt: "lets go ahead with M1 but before commiting i want to check it, so just build it and we ll commit it after i give the go ahead."

Why it mattered: established the review-before-commit workflow we now repeat every milestone — the agent builds and self-tests, the human does their own error testing, and only then do we log + commit.

Mistakes: none functional, but one test-script slip on my side — a mismatched grep pattern during smoke testing made an edit-form check look like it failed. The app was fine; re-running with the correct pattern against a clean DB proved it. Lesson: clean up between test runs and sanity-check the test itself.
